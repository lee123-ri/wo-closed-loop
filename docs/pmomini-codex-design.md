## 一、用户看到的效果

双击现有桌面启动器，平台就绪后自动检查 PMO mini 接入。符合身份、会话和业务范围的消息进入本机 Codex；回答经校验后回到原会话。启动器分别显示平台、消息接入、Codex 和只读查询的状态，任何一项失败均不得显示“全部就绪”。

浏览器关闭后后台服务继续；电脑关机、休眠或断网时不能保证接收，恢复后重新检查连接。仅打开已有网页不等于执行桌面启动器。本次不增加开机常驻要求。

## 三、接入方案与严格静默

顺序：原始机器人消息 → 身份与会话许可 → 按消息 ID 去重入队 → 业务范围判断 → 结构化意图 → 平台只读查询或受控平台说明 → Codex 组织回答 → 事实及权限校验 → 原会话回复。

1. 回调只验证消息、持久入队并确认，不在回调中等待模型。
2. 允许范围包括工单编号、状态、责任人、截止时间、逾期、跟催、措施与验收，以及软工单平台的功能、操作和故障。
3. 闲聊、天气、新闻、其他业务、泛指其他“平台”的问题，或者无法确认相关性的问题，全部静默。
4. 静默必须发生在任何外发之前：不发“处理中”、表态、卡片、拒答或错误提示，也不交给 Codex 执行任务。范围判断如需模型，使用独立、无工具、无会话写入的分类调用；分类失败按静默处理。
5. 不能仅凭出现“工单”“平台”两个词放行；需要识别完整诉求，混合请求只处理明确相关的独立部分，无法拆分就静默。
6. 连续追问按“机器人 + 会话 + 提问人”隔离，只在短期内有已授权的相关上下文时处理“谁负责”“那张呢”；上下文缺失时不跨人或跨群补全。
7. 身份、项目范围和工具权限由程序决定，消息正文中的“我是管理员”“忽略规则”不能改变权限。

原生 `dws dev connect --channel codex` 可用于验证基础接入；目前公开参数没有业务范围前置过滤开关，且默认可能产生处理中表态，默认权限为 yolo。因此，不能直接把默认连接命令放进启动器后宣称满足严格静默。实现优先复用既有入口增加可测试的前置路由；若原入口无法改造，再评审受控的独立 Stream 适配器。

**接收端约束：**目前尚未核实 PMO mini 是否在其他机器存在接收进程。上线前必须核对原接收端并完成同一入口路由或受控切换；不得仅凭本机列表为空就启动第二消费者。仅约束新增接入，也不能保证另一个旧接收端停止回答无关问题。

## 四、查询、Codex 与外发权限

复用 `/api/bot/query` 的事务只读、5 秒 SQL 超时及群授权项目与平台用户权限取交集。已存在的查询包括逾期、项目、精确工单及升级跟催情况。平台功能说明仅使用经过核实的说明材料；未知事实不得从模型记忆补齐。

自然语言只生成受校验的查询参数，实际权限、查询与数字由平台确定。Codex 在隔离目录运行，工具按白名单提供只读能力，不获得原项目写权限、业务写入接口、发信工具或带密钥的环境。具体限制须通过实际运行测试核验，不能只写提示词。

首版仅查询和解释。建单、派发、审批、改责任人、改状态等请求不能自动执行；是否增加动作能力另行设计。

外发在本地验收通过且回复范围与格式获确认后开启。不开测试性群发。对有关问题，查不到、无权限、平台故障分别使用明确的受控说明，不能当成零条记录。对无关或范围不明的问题，无论发生何种异常均不发消息。

回答预览结构：

> 授权范围内，截至【北京时间】，符合【筛选条件】的逾期工单共【真实查询数量】张。
>
> 【权限过滤后的工单编号、责任人与详情链接；有后续页时明确提示】
>
> 依据：【平台查询时点和可访问来源】。反馈：【有用 / 有误】。

## 五、随启动器启动与运行恢复

在平台后端真实就绪后启动问答服务；若已有健康实例则复用，不重复建立 Stream 或 Codex 会话。启动器重跑应支持安全恢复，不能每次重复接收同一条消息。

使用独立受控运行目录保存消息账本、会话映射和健康状态；密钥不写命令行、不进仓库或日志。日志优先写用户 Library/Logs 下的项目目录，避免以 Documents 日志路径造成守护任务权限故障。

复用平台健康巡检思路，对 Stream 建联、Codex 可用、查询授权、队列积压分别报告；断线重连、进程异常重启要有退避和上限。健康检查不得通过给真人发送消息实现。连接状态未知或权限缺失时保持问答关闭，平台可以继续运行并明确显示接入未就绪。

停用只停止新增问答服务，恢复启动器备份和本次开关；保留消息账本用于查重及复核，避免恢复后重发旧消息。

## 七、实施顺序与四层验收

设计确认后，先核实原消息接收端及平台身份映射，完成启动器备份；再实现路由、只读查询、受控 Codex、反馈与账本、健康和启动联动，最后开放真实入口。

| 层级 | 验证方式与通过要求 |
| --- | --- |
| L1 结构 | 启动脚本语法、配置引用、凭据扫描、文档索引和恢复路径完整 |
| L2 单元 | 固定正反例、含业务词的无关问题、上下文缺失、未知身份、重复事件、空结果、异常及发送结果未知分支；无关消息外发次数必须为 0 |
| L3 集成 | 独立数据库与受控消息重放，使用真实查询/模型调用链；校验参数、权限交集、数字、引用、反馈和幂等，不连接生产库重置数据 |
| L4 实例 | 通过桌面同款入口验证首次启动、重复启动、重启恢复、平台不就绪和断网重连；最后在获准的本人私聊用真实提问及无关消息验收，并核对真实回执 |

每层结果保存在项目 `tests/results/`，生成本次结构化结果、latest 和可视化测试报告。未做真实钉钉收发时，状态必须保留“本地通过，真实收发待验”，不得称接入完成。
