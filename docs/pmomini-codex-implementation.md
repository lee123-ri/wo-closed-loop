## 使用与范围

双击桌面的“软工单平台启动.command”，平台后端就绪后自动检查并拉起本机 PMO mini 接入。平台已运行时，也可以通过启动器的 `--bridge-only` 参数仅检查问答接入。浏览器或终端关闭后服务继续；电脑关机、睡眠或断网期间不能保证接收。

私聊直接提问；群聊要求原生 @PMO mini。只处理同一企业的文本消息，并按机器人、会话和提问人隔离上下文。无关问题、语义不明确、分类失败都不发回复、表态、卡片或提示。本机严格静默不代表另一台接收端也静默。

工单查询只读，不执行建单、派发、修改、删除或审批。私聊按稳定钉钉 staffId 唯一匹配有效的平台账号，再应用平台行级数据权限。群聊操作问答开放；具体工单数据还需配置该群的项目范围，并与提问人的平台权限取交集。范围未配置会提示在私聊查询或请管理员配置，不能默认展示全平台数据。

当前支持按编号、区域、状态、项目编码、页码查询；超出现有字段的筛选条件不得忽略后扩大查询。页码范围内空结果和全平台不存在明确区分。逾期口径沿用原机器人查询设计：截止日早于北京时间当天，排除待派发和终态；不是页面所有口径的替代。

## 本机组成

- `backend/pmomini_bridge/core.py`：前置范围门禁、确切常见问法、受限 Codex、SQLite 消息账本与上下文。
- `backend/pmomini_bridge/data.py`：复用平台身份、项目及行级权限，只读事务和 5 秒语句超时；不创建登录会话或业务记录。
- `backend/pmomini_bridge/service.py`：独立 Stream 接收、异步队列、回复出口、反馈与健康检查。
- `scripts/pmomini_bridge_control.py`：单实例启动、状态与停用；launchd 守护仅在显式加载后运行。
- `scripts/start-platform.command`：桌面启动器对应的项目内脚本。

PMO mini 凭据从平台既有受控 `.env` 配置读取，支持现有的 `DINGTALK_ANNOUNCEMENT_APP_KEY`、`DINGTALK_ANNOUNCEMENT_APP_SECRET`、`DINGTALK_ANNOUNCEMENT_ROBOT_CODE`。企业 ID 从平台配置或本机策略读取；不能按机器人名字猜身份。

本机策略、账本及启动前备份位于用户 Library/Application Support 下的 `xh-wo-closed-loop/pmomini/`，权限为目录700、策略和账本600。策略的 `group_projects` 为群 conversationId 到项目 ID 数组的显式映射，空或缺失不开放群内业务数据；兼容存在时的原 BOT_QUERY 群项目授权。该文件不提交仓库。日志在用户 Library/Logs/xh-wo-closed-loop 下。

Codex 保留用户选定模型与模型提供方，仅提取必要的连接配置；不载入个人 MCP、应用或钩子。固定只读沙箱、关闭命令执行、浏览器、外部应用、模型代理等工具，清理子进程环境；认证头仅通过子进程环境传入。不会修改全局 Codex 配置。每次调用是独立、临时的模型运行，必要的查询上下文由账本明确提供，不等于接入桌面当前聊天。

通用 Codex 分类实测较慢，因此常见且完整匹配的查数量、查编号、查页面问法直接走确定性分支；混合任务和新问法继续经过受限 Codex 判断。业务数字由数据库产生，平台说明由核验过的证据片段产生，不采用模型编写的事实。

## 启动、健康与回滚

平台运行环境要求 Python 3.11+、既有 SQLAlchemy/psycopg、python-dotenv、dingtalk-stream、httpx、Codex CLI，以及 macOS launchd。平台当前运行环境已具备，无新增第三方依赖。

管理命令（在项目目录）：

```bash
backend/.venv/bin/python scripts/pmomini_bridge_control.py ensure --human
backend/.venv/bin/python scripts/pmomini_bridge_control.py status
backend/.venv/bin/python scripts/pmomini_bridge_control.py stop
```

健康入口绑定本机 `127.0.0.1:8768/health`，分别报告 Stream、Codex、队列和最近收发。`status=ready` 只代表本机接入就绪，不等于有真实用户消息或已送达回读。不会为健康检查发送钉钉消息。

launchd 配置存放在本机策略目录而非自动登录项目录，由桌面启动器加载；进程异常退出自动恢复，重复启动复用实例。关闭本次问答服务可执行 stop；恢复旧桌面启动器可从同目录的 `launcher-before-codex-20261023.command` 备份恢复。停用不改平台工单、OA或另一个机器人接收端。保留账本，防止重新启用后重发旧消息。

消息账本在重启时将未完成消息标记 unknown，不盲目重发；回调丢弃启动前的历史消息。发送出口仅允许官方钉钉 HTTPS 会话地址，一次尝试，超时和结果不确定均不重试。接口 errcode=0 只记录“受理”，独立投递回读仍另记。

## 验证与验收边界

本地测试命令：

```bash
backend/.venv/bin/python tests/test_pmomini_bridge.py -q
cd backend
.venv/bin/python ../tests/test_pmomini_bridge_db.py -q
```

第二组测试强制使用单独的 `wo_pmomini_20261023_test` 数据库，只生成合成测试记录并回滚，不重置主库。覆盖本人权限、群项目与个人权限交集、管理员受群约束、未知身份、重复身份、未知筛选、伪造编号和 PostgreSQL 只读写保护。

测试报告分别记录 L1 结构、L2 单元、L3 隔离数据库及真实模型、L4 桌面入口/单实例/恢复。真实钉钉往返依用户要求留待下一次主动提问；不能以本地回放或连接成功代替真实送达验收。

九条底线：异步确认、消息幂等、无依据停答/静默、来源、文本反馈命令、差评/无依据待补队列、固定回归集、异常降级及全链回放均有对应实现。反馈命令只认同会话同提问人的已回复记录，“有误”进入待补队列，默认负责人是平台管理员。反馈、拒答及端到端真实消息指标尚需自然运行积累，不能声明已达业务指标。

## 首次真实提问后的回传模板

记录提问时间、私聊/群及是否原生@、消息ID、命中/静默结果、引用和权限范围、API受理与实际客户端看到的内容。无关提问应记录本机外发为0；如另一个接收端有回复，须与本机账本区分。反馈命令应落到同一记录；点错记录或跨人反馈不可写入。

首次真实收发前，端到端 P95、反馈率、未命中率和重复提问率均为待测。通用模型分类已有31–81秒的本地实测，尚未达到标准中的6秒响应基线；常见确定性路径和前置静默不等待模型。
