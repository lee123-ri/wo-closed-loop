# 工单平台 · 外部建单接口文档

> 给外部系统 / Agent / 脚本一个「不登录平台、不经过钉钉 OAuth」就能创建与查询工单的通道。
> 通过一个共享 API Key 鉴权，接口入参全部用「名称/编码」，后端负责解析为内部 ID。

- 接口版本：v1（随 `v0.6.0` 交付）
- 鉴权方式：请求头 `X-API-Key`（环境变量 `EXTERNAL_API_KEY`）
- 数据格式：`application/json`，日期用 ISO 格式 `YYYY-MM-DD`

---

## 1. 鉴权（X-API-Key）

所有外部接口都要求请求头：

```
X-API-Key: <你的密钥>
```

密钥由平台侧配置，**不是调用方自己生成**。服务端配置方式：

```bash
# backend/.env（本地）或 k8s 环境变量
EXTERNAL_API_KEY=<32字节随机hex>
```

生成一个密钥：

```bash
openssl rand -hex 32
```

- `EXTERNAL_API_KEY` 为空 → 外部接口整体禁用，任何请求返回 `503`。
- 该密钥**只有一个、全员共用**（当前设计）；泄露需立即轮换，请按平台密钥管理规范保管。

---

## 2. Base URL

| 环境 | 地址 |
|------|------|
| 本机 / 局域网试用 | `http://10.10.147.200:8000`（后端直连） |
| 生产（ACK） | 以交付的 ALB 域名为准（如 `https://wo.example.com`） |

> 前端 Vite 的 `/api` 代理仅用于浏览器页；外部系统请直接调后端 8000 端口（或生产的 API 网关）。

## 3. 创建工单

### 3.1 请求

```
POST /api/external/work-orders
Content-Type: application/json
X-API-Key: <密钥>
```

请求体字段：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `title` | string | ✅ | 工单标题，1–256 字 |
| `project_code` | string | 二选一* | 项目编码，如 `PRJ-0001` |
| `project_name` | string | 二选一* | 项目名称（精确匹配） |
| `reason` | string | 否 | 触发原因 |
| `action` | string | 否 | 行动要求 / 措施 |
| `person_name` | string | 否 | 责任人姓名（精确匹配，禁用/不存在/同名不唯一会报错） |
| `approver_name` | string | 否 | 审批人姓名；不填则按工单类型的默认审批人解析 |
| `type_code` | string | 否 | 工单类型编码 |
| `type_name` | string | 否 | 工单类型名称（`type_code` 优先） |
| `source_code` | string | 否 | 来源，默认 `external`；可选见「附录 A」 |
| `priority` | string | 否 | `P1/P2/P3`；不填按来源推断（`alert→P1`，其余 `P2`）；非法值报 422 |
| `region` | string | 否 | 区域，见「附录 C」 |
| `planned_start_date` | string | 否 | 计划开始时间，`YYYY-MM-DD` |
| `deadline` | string | 否 | 截止时间，`YYYY-MM-DD`；不填按 SLA 默认天数顺延 |
| `client_request_id` | string | 否 | 调用方请求唯一标识（≤64 字），用于幂等去重，强烈建议传 |

\* `project_code` 与 `project_name` 至少传一个，都传时以 `project_code` 为准。

### 3.2 解析规则（重要）

外部调用方拿不到平台内部 ID，所以实体一律按「名称/编码」传入，后端解析：

- **项目**：`project_code` 精确匹配 `projects.code`；否则 `project_name` 精确匹配 `projects.name`。找不到 → `404`，同名多条 → `409`。
- **责任人 / 审批人**：按姓名精确匹配「启用」用户。找不到或已禁用 → `404`；同名多条 → `409`。**绝不自动建号**。
- **工单类型**：`type_code` → `type_name` 依次匹配 `workorder_type_kb`。找不到 → `404`。

> 找不到就报错，不会猜、不会静默补默认实体——请调用方对接前先核对名称/编码是否与平台一致。

### 3.3 状态语义

外部建单默认落「**待派发（pending）**」，**不自动发起钉钉审批**。由平台内管理员/审批人在工单列表点击「派发」后进入钉钉 OA 闭环。

### 3.4 响应

新建成功返回 `201`，响应体为完整工单（与平台内接口同构），关键字段：

```json
{
  "id": 123,
  "code": "RW-2026-0042",
  "client_request_id": "trace-0001",
  "status": "pending",
  "title": "…",
  "project_name": "通辽永兴风电场",
  "person_name": "王小宁",
  "approver_name": "金惠良",
  "priority": "P2",
  "source_code": "external",
  "deadline": "2026-09-13",
  "planned_start_date": "2026-09-10",
  "created_date": "2026-09-10",
  "...": "其余字段见平台工单详情"
}
```

### 3.5 示例

```bash
curl -X POST "http://10.10.147.200:8000/api/external/work-orders" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: ${EXTERNAL_API_KEY}" \
  -d '{
    "client_request_id": "trace-0001",
    "title": "AGC 双细则考核超标纠偏",
    "reason": "7 月双细则考核扣分超标 15%",
    "action": "排查 AGC 响应延迟原因，协调厂家修模",
    "project_name": "通辽永兴风电场",
    "person_name": "王小宁",
    "approver_name": "金惠良",
    "source_code": "alert",
    "priority": "P1"
  }'
```

```python
import requests

resp = requests.post(
    "http://10.10.147.200:8000/api/external/work-orders",
    headers={"X-API-Key": KEY, "Content-Type": "application/json"},
    json={
        "client_request_id": "trace-0001",
        "title": "AGC 双细则考核超标纠偏",
        "project_name": "通辽永兴风电场",
        "person_name": "王小宁",
        "source_code": "alert",
    },
)
print(resp.status_code, resp.json())
```

## 4. 查询工单

```
GET /api/external/work-orders?code=RW-2026-0042        # 按工单编号
GET /api/external/work-orders?client_request_id=trace-0001   # 按调用方请求标识
```

- `code` 与 `client_request_id` 至少传一个，都传时以 `code` 为准；都不传 → `422`。
- 成功返回 `200` + 完整工单（便于调用方回写状态、做闭环跟踪）；找不到 → `404`。

```bash
curl -H "X-API-Key: ${EXTERNAL_API_KEY}" \
  "http://10.10.147.200:8000/api/external/work-orders?client_request_id=trace-0001"
```

---

## 5. 幂等去重

- 调用方传入 `client_request_id`（如自己的 trace_id / 业务单号）后，**同值重复提交不会重复建单**：
  - 首次提交 → `201` + 新建工单；
  - 再次提交（网络重试、超时重发等）→ `200` + 返回**首次创建的那条工单**。
- 不传 `client_request_id` 时每次提交都会新建一条，请调用方在可重试场景务必带上。

---

## 6. 默认规则

| 项目 | 规则 |
|------|------|
| 初始状态 | `pending`（待派发），不自动发起钉钉审批 |
| 优先级 | 传了用传的（非法 → `422`）；没传按来源：`alert→P1`，其余 `P2` |
| 截止时间 | 传了用传的；没传按 SLA：P1=1 天 / P2=3 天 / P3=7 天，从当日顺延 |
| 审批人 | 传了按姓名解析；没传按工单类型默认审批人（角色 → 人）解析 |
| 编号 | 系统自动分配 `RW-<年>-<四位序号>`，调用方不可指定 |

## 7. 错误码

| 状态码 | 含义 |
|--------|------|
| `201` | 新建成功 |
| `200` | 幂等命中（返回已建工单）或查询成功 |
| `401` | 缺少 `X-API-Key` 或密钥无效 |
| `404` | 项目/责任人/审批人/工单类型/工单不存在 |
| `409` | 名称同名多条，无法唯一确定（请改用编码） |
| `422` | 缺少必填（项目、标题）或值非法（优先级等） |
| `503` | 服务端未配置 `EXTERNAL_API_KEY`，外部接口未启用 |

错误响应体统一为 `{"detail": "…"}`。

## 8. 附录

### 附录 A · `source_code` 取值

| code | 名称 | 含义 |
|------|------|------|
| `external` | 外部接入 | 默认，本次对外接口的通道标识 |
| `alert` | 监视告警 | 异常指标类，默认 P1 |
| `plan` | 年度计划 | 年度计划类 |
| `meeting` | 判定会 | 判定会决议 |
| `manual` | 手动 | 手动录入兜底 |

> 老库若未初始化 `external` 来源（见 `config/system.yaml` 的 `seed.sources`），工单列表的来源筛选会显示原始 code；可在「规则配置 → 来源」或调 `POST /api/config/config-definitions`（category=source, code=external, name=外部接入）补一条。

### 附录 B · `priority` 取值

`P1` / `P2` / `P3`（也接受 `1/2/3`、`高/中/低` 等写法，服务端自动归一；无法识别 → `422`）。

### 附录 C · `region` 取值

`华北 / 华中 / 华东 / 华南 / 西北 / 西南 / 东北`（省份/组织名会自动归一化为大区，识别不了留空）。

---

## 9. 安全提醒

- `X-API-Key` 走**明文请求头**传输，生产务必走 HTTPS（ALB 已终结 TLS）。
- 密钥单点共享，泄露即全通道失守：请限制密钥分发范围，泄漏后立即轮换 `EXTERNAL_API_KEY` 并重启后端。
- 外部建单默认不触发钉钉审批，避免外部系统批量灌数据时误发 OA；等平台侧人工派发后再进入审批流。
