# 年度计划派发与异常原因工单路由设计

- 状态：实施中
- 日期：2026-09-18

## 目标

1. 年度运营计划继续只扫描钉盘“定稿”和“初稿”两个指定目录的“工单版”文件，且仅导入非 EAM 行。
2. 新导入、计划开始日在当月的完整计划，立即尝试发起 OA；后续月份保留 `scheduled`，由对应月份 1 日 09:00 派发。
3. 异常指标仅在每天 10:00、15:00 从 AITable 增量读取。新增记录先创建平台“原因工单”，路由责任人查看和回填；禁止由同步任务自动生成措施工单、发起 OA 或发送消息。

## 边界

- “原因工单”使用既有异常主单：`status=pending`、带 `metric_type`，在责任人回填原因和拟采取措施前不进入措施工单阶段。
- 双细则表自带原因/措施时也只创建异常主单（`judging/confirming`），仍由后续人工确认动作生成措施工单。
- 本次不改变 AITable 已有记录的差异更新语义；增量以来源记录 ID 去重，只处理新增记录。
- 不发送钉钉聊天、群消息或邮件。

## 验收

1. Beat 的异常任务为北京时间每日 10:00、15:00，而非五分钟轮询。
2. 异常同步的返回值仅包含原因工单数量；同步路径不调用通知服务。
3. 钉盘导入当月计划时调用月度派发器；未来月份仍为 `scheduled`。
4. 全部测试使用隔离数据库和 mock 的 OA/DWS 调用，不触达真实外部服务。
