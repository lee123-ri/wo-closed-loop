## 三、差距分析（按优先级排序）

### 🔴 P0 — 不补就缺胳膊少腿

**1. 设备台账（工单关联设备）**

现在工单只关联"项目"（电站），不关联具体设备。行业里每张工单都挂在设备上。

缺失影响：
- 不知道哪个设备出了多少次问题
- 无法做设备健康度分析
- 甲方报表里看不到设备级别的运维记录

补强方案：
```
WorkOrder 表新增字段：
  equipment_id   → 关联设备
  equipment_type → 风机/逆变器/箱变/SVG/线路
  component      → 变桨系统/齿轮箱/发电机/IGBT模块

新建 Equipment 模型：
  id, name, type, station_id, sn, model, install_date, status
```

**2. 缺陷故障分类知识库**

现在异常指标工单靠人工看标题判断类型。行业里都有标准化的故障代码体系。

补强方案：
```
新建 DefectCode 模型（三级分类）：
  L1 系统: 风机/光伏/储能/电气/控制
  L2 子系统: 变桨/齿轮箱/逆变器/汇流箱
  L3 故障模式: 异响/过热/振动超标/效率低

工单创建时：选择故障代码 → 自动匹配SOP → 自动推荐优先级
```

---

### 🟡 P1 — 显著提升专业度

**3. 报表导出**

甲方月度/季度需要运维报告。现在只能看屏幕，不能导出。

补强方案：
```
GET /api/dashboard/export?view=client&format=pdf&project_id=X&month=2026-08
GET /api/dashboard/export?view=ops&format=xlsx

前端：工作台增加"导出报表"按钮
```

**4. 通知/提醒增强**

现在只有 SLA 升级通知。缺少：
- 截止日期前一天提醒
- 新工单派发通知
- 回填催促（逾期未回填）
- 验收催促

补强方案：
```
Celery 定时任务：
  - 每天 8:00 扫描即将到期的工单 → 钉钉通知
  - 每天 10:00 扫描逾期未回填的工单 → 催促
  - 新工单生成 → 立即通知责任人
```

**5. 知识库/SOP 联动**

`WorkOrderTypeKB` 现只有 name + desc。行业里 SOP 是结构化的检查清单。

补强方案：
```
WorkOrderTypeKB 扩展：
  sop_steps: JSONB  → [{step:1, action:"检查XX", standard:"<XX值"}]
  safety_measures: JSONB → ["断电确认", "挂接地线", "佩戴PPE"]
  tools_required: JSONB → ["万用表", "力矩扳手"]
  parts_common: JSONB → ["轴承", "密封圈"]
```

---

### 🟢 P2 — 锦上添花

**6. 移动端（钉钉微应用）**

你说了 PC 优先，但现场人员在电站现场用手机。行业标配是移动端。

**7. 两票管理**

工作票/操作票是电站安全合规要求。但这是独立模块，复杂度高，建议先不做。

**8. 备品备件**

工单处理需要消耗备件。但这需要独立的库存管理模块，建议先不做。

## 四、推荐补强路线图

```
当前 ──────→ P0 (2周) ──────→ P1 (1.5周) ──────→ P2 (按需)

P0: 设备台账 + 缺陷分类
P1: 报表导出 + 通知增强 + SOP知识库
P2: 移动端 + 两票 + 备件
```

### P0 具体改动量

| 模块 | 后端 | 前端 | 估时 |
|------|------|------|------|
| 设备台账 | Equipment 模型 + CRUD API + 工单关联 | 设备列表页 + 工单创建设备选择 | 2d |
| 缺陷分类 | DefectCode 三级分类模型 + 种子数据 | 工单创建级联选择 + 自动匹配SOP | 1.5d |

### P1 具体改动量

| 模块 | 后端 | 前端 | 估时 |
|------|------|------|------|
| 报表导出 | PDF/Excel 生成 + 导出 API | 导出按钮 + 参数选择 | 1d |
| 通知增强 | Celery 定时任务 + 提醒规则 | 通知配置页 | 1d |
| SOP知识库 | 扩展 WorkOrderTypeKB + 种子数据 | 工单详情展示SOP | 0.5d |

## 五、我的建议

**先做 P0 的两件事：设备台账 + 缺陷分类。** 这两个是行业标配，不做就缺了关键维度。做完后每张工单都知道"哪个设备的什么问题"，整条数据链路就完整了。
